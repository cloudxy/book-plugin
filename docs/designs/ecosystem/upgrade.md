## 〇、两条能力主线

顶层按用户确认分为两条主线。书籍/人物是蒸馏对象的分类，阶段 Skill/工具是实现能力的手段，成品 Skill 是交付物，均不另列为顶层主线。

| 主线 | 职责与优化对象 | 必须改善的结果 |
|---|---|---|
| 1. 蒸馏能力 | 全文阅读、按内容与用途取舍、知识/思想/叙事/表达重建、跨单元综合、方法与应用范例生成、来源复核、Skill 构建及实际运用；优化相应阶段指令、范例和工具 | 提高完整性、忠实性与新任务运用能力，减少答非所问和拼抄；产出可迁移的书籍/人物 Skill 及准确组合清单 |
| 2. 编排与调度能力 | 将蒸馏需求组织为任务及依赖，选择合适阶段 Skill/工具，安排执行顺序、并发与汇合、上下文和预算，管理状态、缓存、恢复及定向重跑 | 更少等待、重复阅读、无效调用和人工协调；批量任务稳定完成，同等质量下提高吞吐并降低时间与费用 |

两条主线通过明确的任务输入输出协作：蒸馏阶段声明所需材料、能力、产物和语义问题；调度层安排执行、收集结果并按依赖处理失败。蒸馏判断决定哪些内容缺失或错误，调度据此重跑必要阶段；调度状态本身不能判定语义通过，也不能以节省预算为由跳过全文阅读。

蒸馏线分别记录完整性、忠实性、机制运用及任务交付表现；编排调度线记录耗时、费用、吞吐、重复执行和人工干预。最终以相同任务范围下可用 Skill 的质量和生产成本共同判断收益。研究方法可以优化两线的指令、范例与执行策略，模型参数始终不变。

其中“阶段”是可观测的任务模块，不要求每阶段创建独立代理或新增一个顶层 SKILL.md；先沿现有主技能、references、commands 与 bridge 形成清晰的模块边界。涉及作者认知与表达的任务仍联合重建，不能为并行而拆成互不相干的两套模型；知识用途不强制重建作者口吻。

改进有两条反馈路径：单书运行发现问题，定向修该书的材料或候选；跨书发现可重复的问题，修工作流的分工、指令、范例或工具，并在其他书上验证。只修好一本书，不能据此宣布通用流程升级成功；只让中间模块得分更高，也不能代替最终 Skill 的效果。

## 二、要求与完成口径

| 要求 | 应交付什么 | 如何证明 |
|---|---|---|
| 编排能力 | 按依赖执行、按预算分配、能汇合/恢复的生产流程 | 阶段耗时与调用记录可追溯，阻塞、重复作业和失效缓存被正确处理 |
| 工作流 Skill 能力 | 有明确合同、适用范例和失败处理的阅读/重建/综合/评审模块 | 修模块后下游失败减少，完整产物改善；其他书上可复现，不只提高模块自评分 |
| 两类 Skill 与组合清单 | 书籍 Skill、人物 Skill 及索引这些包的中立清单 | 至少一个真实书籍包和一个真实人物包能运行，清单路径/版本/已测范围与原包一致，不能只登记人物姓名 |
| 按内容取舍 | 按任务选择知识、思想、叙事和表达资产及对应验收 | 知识任务能运用原理和条件，作者任务能迁移判断方式，文学任务能运用叙事或表达机制；不强制全部成品扮演作者 |
| 产能优先 | 给定原文、用途、档位，产出能完成声明任务的 Skill；不让用户手填 YAML 或逐步点继续 | 一部真实书形成被实际测试的完整 Skill，记录干预、耗时、token、失败与返工 |
| 真蒸馏 | 所选整书边界内全文处理，保留语境、声音与条件；局部任务明确标局部 | 阅读任务底账、原文定位、自动语义抽样；无可提取材料的单元也说明处理结果 |
| 验证分级 | L1 内部材料、L2 可迁移试用 Skill、L3 正式验收 Skill 有不同交付深度 | L1 不冒充成品；L2/L3 都须真实运行，完成档绑定回执，改标签不能升档 |
| 独立可用及迁移 | 完整 Skill 包可以复制到独立工作区，在声明的宿主条件下执行 | 干净会话只加载包、任务及声明依赖，完成回答或成文；用户随后自行迁移 ncc |
| 持续批量 | 并行产出 Skill、断点恢复、失败隔离、增量重跑 | 两书运行，一书中断恢复；不重复已完成单元、不混包；分别留下 Skill 实测结果 |
| 兼容与私有边界 | 保留旧包和已有任务解释口径，原文与产物留私有目录 | 老合同回归、原候选发布绑定保持；旧分数不转换为新档位 |

收益按质量与资源分项衡量，不用单一平均分抵消关键失败：同等质量下是否更快、更便宜、更少人工；同等预算下是否更忠实、更完整、更能解决新任务。记录首个可用 Skill 时间、总耗时/token/费用、用户干预次数、自动返修、阶段一次通过情况、重复调用/缓存复用，以及成品的来源忠实、机制运用、表达与任务完成表现。成本包含失败、重试、评审和优化器自身调用。并行缩短墙钟时间不等于减少模型费用，二者分别报告。

运行记录同时绑定 workflow_version、阶段指令/工具版本、输入快照及最终 build_id，才能区分收益来自编排、阶段 Skill、模型选择还是成品修订。材料数、文件数和代理数只作过程诊断，ncc 卡片接收率不作为指标。

先测同一本书、同一阅读/能力范围、同档 Skill 的串行基线，再对比自动线；两书并行与同档串行比较吞吐。L1 材料与完整 Skill 范围不同，不能比较它们的成本后宣称等质提速。首轮跑前固定预算和期望改进，跑后报告观察值及瓶颈，不虚构百分比收益或统计结论。

## 三、分级合同

先定产品对象（book/person）和能力用途，再选交付深度。二者不能混成一条“从知识材料升级为作者分身”的阶梯。知识 Skill 达到声明用途即可作为成品，不必晋级成作者口吻；人物 Skill 也不能因姓名条目存在就视为已生成。以下为新合同草案，具体数据结构及与现行 book-skill/2 的兼容在 P0 明确。

| 档位 | 必需产物 | 通过条件 | 可用范围 |
|---|---|---|---|
| L1 内部材料 | 固定版本源材料、overview、阅读底账、类型条目、定位及抽样回执 | 结构/版本/依赖校验 + 自动独立分层抽样；关键失败修复或隔离 | 后续构建的输入或断点；停在 L1 不能宣称 Skill 交付完成 |
| L2 可用 Skill | L1 材料 + 用途对应的能力核心、条件、完整范例和自包含包；思想/作者用途补 episodes、习惯/路径，表达用途补 PROFILE 等资产 | 核心及必要来源关系独立复核 + 适用任务实际运行 + 移目录运行；六组为初始覆盖配置 | 声明范围内可调用、可迁移的试用 Skill；知识包无须具备作者口吻，作者包不冒称整书正式分身 |
| L3 正式验收 Skill | 现行作者/整书分支的完整资产、正式来源复核、行为验收及用户口吻记录 | 继续按现行 15 组及运行目标覆盖，纳入适用诱饵/未见/混淆题，用户审阅完整回答 | 当前含义保留；不强迫知识产品走作者口吻验收，其他正式产品合同须另行明确定义 |

档位是交付深度，不是书籍类型或笼统事实可信度。以 Skill 为目标的任务至少推进到已实际验证的 L2；L1 只作阶段成果。所有档位保留准确定位、来源角色和状态；适用程序依赖继续走原四闸。

### L1 抽样、返修与有限交付

按章节、类型、声音与重建程度分层；初始样本数为 min(N, max(10, ceil(0.1*N)))，另覆盖关键数值/单位、因果外推、跨单元关系和声音混淆等高影响条目。记录样本 ID、选取规则及输入哈希，不能由提取者专挑容易条目。这是业务抽查配置，不是统计置信保证。

独立评审读取原文上下文，核对忠实性、限定、声音及用途。关键误归属或反向结论触发对应章节/类型扩大抽查；系统性错误暂停该批，其他合格批次继续。默认最多返修 2 轮，可配置；仍不通过则隔离并列出缺口，不把部分可用误报为整档完成。

用户不承担固定“抽 10 条”任务。宿主无法提供独立评审时交付待核候选，后续由独立会话补核；主代理自评不改称独立通过。

### L2 与 L3 实测范围

L2 初始六组：直接应用、跨单元组合、条件变化与不变、多轮纠正、按要求交付、范围外或来源混淆。“交付”按用途选解释/计算/方案/叙事/表达，知识包不强测作者语气。保留实际输入、回答、可得加载记录和独立评审；推演、效用、作者认知/表达沿用现行适用评分与最低线，不适用项明确说明。未覆盖的运行机制缩小范围或补题，不以“六题做完”替代覆盖。

L2 须增加明确的试用 Skill 构建模式与回执，不能向现行 build_candidate 填不完整复核来绕过合同；打包形态仍为可迁移完整 Skill，试用与正式验收状态分别标记。L3 新题型映射到已有 15 组和正常/变化情境，只有缺口才加题。匿名标签、独立评审和评分依据隔离可自动执行；不满足双盲条件时如实称匿名评审。

升档复用版本一致的原文、定位及已核结论，按依赖图补增量；包变更生成新 build_id，旧答文只作历史证据。L1 未保留机制或声音信息时须补读，不能宣称自然拥有 L2 能力。

## 四、实际执行与断点恢复

### 1. 从原文到资产

输入登记原文、版本/译者、正文边界、用途、目标档、宿主适配和预算。预处理保存原文件/规范文本哈希，以及回到章节、页码或时间轴的定位映射；OCR、缺页、附录与译注问题单列。

逐字锚点在拟议新分支中可选：默认保存自动位置 ID、对应上下文及版本信息；只有需要精确引文的任务才保存相应摘引，不要求用户手填，也不要求所有能力节点复制原句。现行 0.4.0 来源合同中的强制锚点要求不因文档修订自动消失，实施时必须修改对应 schema/校验与兼容规则，旧包按旧合同解释。

按结构单元安排全文阅读，依宿主上下文预算拆窗口。全部声明正文实际进入阅读任务，抽查只用于验证，不能替代全文处理；超上下文时分批完成，不只读首尾或用摘要代替缺失正文。未闭合的论证/场景登记接读，不能按字数截断认识路径。独立阅读计划是底账，条目列表不能反向充当阅读证明；保存实际任务输入、执行回执、局部发现及输出哈希。记录与语义复核共同提供证据，哈希仅校验内容及定位，无法证明模型已读或理解。

宿主模型/代理完成语义提取，Python 管计划、状态和校验。可执行适配器提供 dispatch/collect；只能出任务单的宿主标为 assisted，不能宣称全自动。无执行器在开工时报告，不把填空 YAML 转交用户。

局部结果落盘后按稳定来源 ID 合并、消歧、保留冲突和核对跨章关系，再生成总览、材料与复核任务。优先按书并行；书内窗口可并行读取，但跨章综合须汇合，各窗口不能独立宣布整书结论。

### 2. 类型模板须产生不同内容

类型可多选，混合书按单元组合模板，不强迫所有书生成概念—命题—关系表。

| 模板 | 核心对象 | 必留边界 |
|---|---|---|
| 论说/思想 | 问题、概念区分、价值判断、命题、依据、推演、反例、条件 | 作者/被引者/编者分开；主张不自动成为事实，不把所有论说硬改成操作步骤 |
| 文学/叙事 | 社会观察、思想与情感、场景、视角、信息揭示、选择与后果、写法及读者效果 | 作者/叙述者/人物分层；可以提出问题而没有答案，不强造解决方案；故事内机制不外推现实 |
| 网文/连载 | 人物动机与关系、情节完整性和新奇性、节奏、章末钩子、主暗线交织、伏笔兑现及情绪推进 | 从实际文本归纳，不把“每章必须钩子”等风格倾向固化成所有书规则；不重启已取消的斗破整书任务 |
| 诗词/韵文 | 意象、章法、转折、声音与情感推进；格律/形式单列 | 可确认形式与解释假说分开，不强造哲学关系图 |
| 科学/专业及其他领域知识 | 书内知识（定义、原理、因果、公式、单位、前提、时效）与适用的解释/论证/操作方法；历史等领域另保留事件、时序及证据关系 | 来源忠实与现实有效分开，推断/争议/时代条件明确；不强制作者画像，不用“素材齐了”代替可运用知识；适用程序另走四闸 |

科学类外部批评研究仍留 backlog；条件、版本、时间及“现实未核”标签属于消费所需信息，不重新引入被否决来源。

### 2.1 人物 Skill 的独立输入路径

人物线复用 nuwa 的材料调研、框架提取与应用检验流程，产出能按人物方法判断新问题的实际 Skill。登记人物、材料清单、来源角色、时间范围和可访问范围；区分自述、作品、他人评价及后世解释，保留思想演变和不同阶段的矛盾，不把一个时期结论写成终身立场。

用户提供整部作品作为输入时仍全文阅读；网络调研只可声称覆盖已实际获取的材料，不冒称读完未取得的作品或完整还原此人。书籍包保留本书的特定框架，人物包可综合多来源但逐项保留归属，不用人物通用模板覆盖本书差异。选取的公开人物 Skill 可复用为输入或基线，只有实际加载、应用和迁移验证后才计为可交付包。

书籍与人物两类蒸馏对象共用执行记录、构建、缓存、返修和组合清单，源材料及重建合同分别处理。人物观点不构成现实事实的自动证明；人物包承担方法/视角能力，事实主张仍回到相应来源与状态。

### 3. 单一状态源与调度

拟以 pipeline/state.json（pipeline/1）为执行状态事实源，PIPELINE_STATE.md 只呈现摘要。scope.reading/reconstruction/runtime/acceptance 保留范围语义，独立记录 target_tier、已验证能力和回执，不把档位塞入 runtime 文本。

最小状态：queued → reading → reconstructed → reviewed → built → tested → delivered；异常为 failed / blocked / stale。记录 task_id、input_hash、策略/提取器版本、owner/lease、attempt、checkpoint、output_hash、build_id、回执和预算消耗。完成状态由有效产物和实际试答推导；built 不等于 tested，L1 材料就绪也不等于 Skill delivered。

提供 plan/run/status/resume 能力，具体 CLI 名称由实现统一。默认并发上限 2，按宿主能力和预算调整；每本书只有一个汇总写入者。任务领取加锁及租约，超时释放后恢复，失败有限退避重试；不支持并行时串行执行，不跳过语义步骤。

checkpoint 绑定原文/单元/策略/提取器版本。原文变化重算受影响单元；material、PROFILE 或核心变化使相关回执 stale。相同输入及有效输出才复用缓存，不凭文件存在或旧 passed。到预算边界保存成果，列出未完成任务；不删除失败证据，也不无限返修。

### 4. 把全流程表示为有依赖的任务模块

基础链为：固定原文/定位 → 全文阅读及完整片段 → 跨章联合重建 → 核心与应用范例 → 来源复核 → 构建 → 实际运行与评审 → 交付。重建、范例和复核允许按失败原因有限回到对应模块；输入变化只使其下游依赖失效。

每个模块声明输入、输出、所需源材料范围、前置依赖、执行者能力、适用工具、预算及失败返回目标。先使用现有宿主的执行和工具能力；无相应能力时明确降为串行或 assisted，不另假设模型 API、后台服务或无限并发已可用。

独立阅读单元和不同书可并行；跨章综合等待必要材料齐备。全书最终模型设一个合并写入者，局部任务只提交带来源 ID 的结果。独立评审不复用生成者的自我解释作为事实；它读取必要原文、产物和固定评分依据。

共享不可变原文索引、已定位片段及版本一致的中间结果；各任务只装载所需上下文和依赖闭包，不反复传整本书及完整聊天历史。上下文裁减要保留逻辑边界和来源角色，不能因省 token 丢掉改变判断的限定。无法由机械校验证实的事项仍交语义检查。

### 5. 失败归因决定返修位置

记录可观察的输入、输出、工具调用和评审证据，不要求模型内部思维。将一次最终失败沿来源/依赖 ID 追到可检查的阶段；归因不确定时用小范围重跑或替换组件比较，不能仅凭模型自述确定原因。

| 失败表现与可查证据 | 优先检查/修复的阶段 |
|---|---|
| 原文限定、反例或场景后果未进入阅读结果 | 阅读范围、单元接读及提取指令；补对应源段后重建受影响节点 |
| 局部片段准确，跨章后关系方向或声音归属错误 | 综合指令、冲突处理、角色分层及合并合同 |
| 模型关系准确，实际题中不会选择或组合 | 核心编排、触发/条件说明、完整应用与变化范例 |
| 范例在包内但未被运行时使用 | 构建索引、入口提示、资源路径及宿主加载方式 |
| 回答满足结构而语义错误，评审仍通过 | 评审依据、评分粒度、负例及独立性；评审器自身须校准 |
| 已通过步骤反复执行、不同任务抢写或等待 | 调度依赖、缓存键、租约、预算分配和恢复逻辑 |

修复动作绑定模块版本与受影响资产，重跑最小必要范围；没有证据不把下游出错都归为“模型不行”，也不一律增加成品提示词或全流程重蒸馏。

### 6. 两层优化循环

**单书循环**：当前工作流产出候选 → 在实际宿主运行开发任务 → 独立反馈 → 定位生产阶段 → 提出少量修改 → 重跑受影响阶段/任务 → 选择候选。开发范例、候选选择集和最终保留题分开，源材料限定始终可追溯。

**工作流循环**：汇总多书可重复的失误和成本 → 提出阶段指令/范例、分工、上下文或调度策略候选 → 固定数据/模型条件比较 → 在未参与调优的书或来源单元上检验 → 将有效规则纳入新的工作流版本。只在一本书验证过的经验保留为书级或类型级建议，不能直接升为全局规则。

优先一次改变一个可归因模块，再做有记录的联合调整。使用原文样本和真实工作任务建立开发集；验证按来源单元、机制和书籍隔离，不靠同故事换名称制造未见任务。样本少时明确证据范围，不宣称跨类型泛化已经成立。

通用工作流只积累可复用的操作规则、工具改进和合成教学示例；真实书稿、产物、答文与评审留 books/ 或 .work/，不得因“优化经验库”进入远端。生产中采用固定版本的工作流；优化器在私有实验中提出候选，经检验后走正常版本更新，不静默改已发布包或进行无界自治修改。

### 7. 预算随证据分配

能确定计算的定位、哈希、字段、依赖及路径检查交给脚本；需要理解的阅读、综合和评审使用宿主模型。先测各阶段成本和效果，再决定是否改变模型配置、并发、样本数或上下文大小；不先假定更多代理、更强模型或更长提示必然更好。

对确定失败的节点先做局部诊断；只在出现跨章冲突、缺失关键上下文或无法归因时扩大范围。分级验证沿第三节执行。优化每轮有调用/token/时间上限，无收益时保留已有合格版本；预算耗尽只结束本轮搜索，未完成的原始任务仍如实列出。

## 五、Skill 可用性与可迁移交付

### 1. 两个项目的责任边界

book 负责书籍/人物材料蒸馏、Skill 生成、独立运行验证，以及完整包和组合清单交付。用户自行把 Skill 迁移到 ncc，并决定在那里如何调用或组合。book 内部编排负责生产任务，下游写作侧编排负责使用这些 Skill 完成创作；两者不能混为同一职责。book 的完成条件不依赖 ncc 的素材编号、知识清单、内部状态、数据库或写手包。

现有 export_portfolio.py 中面向 ncc 素材卡/claims.jsonl 的特定出口，以及自动迁移，退出本轮关键路径。组合清单功能保留并改为索引完整 Skill；不能因取消 ncc 适配而一起取消清单，也不能把修复素材导出当成“Skill 已能用”。

组合清单是必交付项：索引完整 Skill 的稳定 ID、相对路径、book/person 对象、作品版本或人物时期、用途/触发条件、输入输出、能力及禁用范围、依赖、包版本/build_id/内容哈希、已测任务及宿主条件。用这些字段支持下游选择和组合，不预设 ncc 内部格式，不执行写作调度或写入其他项目。

组合清单和包形成可整体复制的目录；路径在目录内可解析，版本与被测包一致，重导出正确移除清单中的旧引用。没有实际 Skill 的人物/书籍条目只标待构建，不能计入可用 Skill 数。已测范围是事实记录，不能手填更高档位改变它。

### 2. 一个可交付 Skill 应包含什么

沿用现行构建器的单入口结构，先复用已有能力，再补缺口：

- SKILL.md：明确何时调用、解决什么任务、必要输入，以及已经重建的核心与运用方式。
- 包内 references：运行需要的机制、适用条件、反例、完整范例和必要来源材料，入口能按任务找到它们。
- 适用的脚本、资源与程序索引：执行路径在包内，外部工具、版本和权限需求显式声明。
- manifest：内容/依赖清单、包哈希、能力范围；交付说明另列实际测试条件、通过项目与未覆盖项。

默认分析、解释或写作任务使用包内机制，不依赖 book 工作区、私有蒸馏日志、生成会话记忆或 ncc 代码。精确查原文等本来需要额外材料的任务应声明材料需求；不能为了正常回答新问题就要求迁移整套书稿和开发环境。

已有 verify_package 校验文件哈希、单入口及 Markdown 相对链接，并已有合成包复制后校验测试。它们保留为自动检查，但不等于真实宿主已经加载或实际任务已经完成；还需覆盖脚本命令、配置和提示正文中的运行依赖，防止仅链接合格而调用仍引用旧绝对路径。

### 3. “能用”的验收以实际行为为准

| 维度 | 如何验证 | 不通过情形 |
|---|---|---|
| 可发现、可加载 | 在声明的宿主新会话中按入口说明调用，记录可得的读取路径和实际执行 | 只在生成它的会话里有效；运行入口或必要内参无法找到 |
| 会运用 | 给一个原书没有现成答案的新问题，产出所要求的解释、判断、方案或作品；评审核对哪些蒸馏机制实际起作用 | 只复述目录/概念、拼原句、模仿词气，或退回通用回答而无机制证据 |
| 会随条件变化 | 改变关键前提、补充事实、切换篇幅或任务，核对受影响判断和保持不变的部分 | 不顾条件照搬结论，或改变无关信息就丢失核心能力 |
| 守住材料边界 | 对声音归属、未知事实、推断、现实变化按用途正确处理 | 把人物台词当作者主张，把书中观点当现实已核事实，把新推演冒称作者原话 |
| 可迁移 | 原包复制到独立临时项目，在原工作区不可访问或具备可核实访问限制的会话中复跑关键任务；不使用 ncc | 依赖原目录绝对路径、旧会话记忆、漏带范例/资源/脚本，或缺少未声明依赖 |
| 有适用范围内的价值 | 关键新题用同模型、同事实、同预算的无 Skill/旧包对照检查具体差别，复用已有有效基线 | 仅文件更多、回答更长或引用更多；没有证据显示新增机制发挥作用 |

这些检查并入 L2 六组和 L3 既有套件，避免再叠一整套重测试。关键新题和迁移后的复跑保存真实输出；移目录后的同题用于迁移回归，不冒充新的保留题。只测了某一宿主就只报告该宿主条件，其他宿主适用性如实标未验。

L2 至少完成声明范围的新任务及迁移验证，交付时标为已测范围内可用的试用 Skill；L3 继续满足整书正式验收与用户表达审阅。当前世界事实按任务需要另核；unresolved 保留为缺口，不进入可断言核心。已有合同对此的约束继续有效。

### 4. 把被测包原样交给用户

只交付实际被测的那份包；内容改变则重建并复验受影响任务。用户可以整体复制 Skill 目录，验收说明和开发评审与运行包分开，避免评分依据进入运行上下文。正常使用不要求调用 book 的构建/审计脚本。

包生成与替换沿用现有 staging、完整性检查和快照机制，迁移路径变化不应改变能力内容。声明运行环境与依赖，不假称零依赖或所有宿主已验证。本轮不实施用户向 ncc 的迁移，也不把目标项目的特定编排当成 Skill 已可用的前置条件。

### 可用于工作流优化的研究方法

以下是针对本项目的工程候选，采用判断基于论文/可检查实现及本地验证，不以名字或论文成绩代替书籍蒸馏效果。全部限定在调用现有模型的工作流层，不引入模型训练。

| 方法及一手来源 | 研究支持的能力 | 在 book-workflow 中的落点 |
|---|---|---|
| [DSPy](https://arxiv.org/abs/2310.03714) | 将多次模型调用组成模块化程序，以目标指标优化程序 | 明确阶段输入输出和端到端指标；借其方法组织现有技能，不要求先整体迁移到某框架 |
| [MIPRO](https://arxiv.org/abs/2406.11695) | 联合优化多阶段程序各模块的指令与示范 | 阅读、联合重建、范例生成、评审各有候选指令/示范，依据成品表现选组合；不能只看单模块漂亮输出 |
| [GEPA](https://arxiv.org/abs/2507.19457) | 从真实执行反馈提出和比较文本组件修改 | 将可定位的失败反馈给相应阶段，搜索有限候选；用于生产阶段 Skill 和成品运行说明均可 |
| [ACE](https://arxiv.org/abs/2510.04618) | 结构化、增量地积累和整理上下文策略 | 保留有效规则、条件及反例，定向增补或修订工作流经验；私有书籍知识与通用经验分开 |

这些方法不自动替本项目定义正确任务依赖、处理书籍声音或保证源文忠实。阶段顺序、并发和上下文预算的优化由本地可配置策略及受控对照承担；不得把提示词优化器宣传为已经具备自动设计整条蒸馏流程的能力。

先做模块合同、运行记录和失败归因，再试一个优化器；MIPRO 与 GEPA 可作候选方案比较，不默认串联部署全部工具。来源完整性、用户范围、私有边界、独立评审及被测原包绑定是固定约束，不交优化器自由删改以换取分数。

## 七、实施顺序与验收

P0 明确两线的协作接口与基线；P1 优先打通蒸馏产出及最小执行链；P2 加强编排与调度；P3 依据实际瓶颈继续优化两线；P4 完成集成。两线共同演进，阶段顺序不意味着先建完一套独立蒸馏系统，再另建一套调度系统。

| 阶段 | 实施内容 | 退出条件 |
|---|---|---|
| P0 模块合同与基线 | 固定 book/person 两类输入、用途资产与组合清单合同；明确可选逐字锚点的版本迁移；复用构建/验证/评测，测流程成本和缺陷 | 可追溯一次运行的阶段成本与结果；R1–R8 均有实施落点；L1 不算成品，不用新分支绕过旧合同 |
| P1 两类 Skill 最小业务闭环 | 先接通一本书阅读/重建/构建/应用，再接通人物材料调研/综合；补适用运行评审、迁移及中立组合清单，打通命令入口 | 至少一个真实书籍包、一个真实人物包及一致清单可整体取走；实际新任务和迁移复跑通过；自然出现的失败完成定向返修，无实际失败则如实标未验证该项 |
| P2 编排与效率 | 在 P1 业务链上加依赖调度、并发、上下文分配、预算、缓存及恢复 | 至少两书运行、中断恢复和输入变更重跑；各包有实测；分别比较墙钟、费用、干预和质量；返修收益只按实际观察报告 |
| P3 工作流 Skill 优化与类型扩展 | 小范围试验 MIPRO 或 GEPA 式阶段优化，按 ACE 式增量记录经验；扩充类型覆盖，至少包括知识与思想/叙事两种不同用途；用其他书验证改进 | 候选工作流与基线同条件对照，完整产物改善；知识用途不依赖作者口吻模板，未见书结果单列，未经验证类型保持待验 |
| P4 0.5.0 集成 | 主技能/references/commands/bootstrap/CLI、版本兼容、四份清单和文档；L3 题型映射及影响复验 | make e2e、make doctor、声明宿主加载和迁移运行检查；Skill 可用性/产能记录与逐书正式验收分开 |

毛选整书为独立 L3 任务，不将其全部做完设为 L1/L2 产能升级前置。已有材料可作回归输入，新档任务/评审不能继承旧分数；上游 Mao/Sunzi 包若作对照，先固定实际版本、材料范围与运行条件。

“不影响毛选”须有技术保证：当前 engine_hash() 对全部 bridge Python 文件取哈希，新增原型会改变未来候选的构建 provenance。实施时明确 0.4.0 解释器/构建依赖快照与新线隔离，或记录影响并按原候选续跑；不无故重建已有候选，也不把新构建冒记为旧被测包。旧绑定包能否发布仍按实际合同判定，不仅由全局代码哈希变化推断它必然失效。

### 最少必要验证

自动合同回归覆盖：跨度不证明阅读、低档冒级、未解决/人物/小说材料误入可断言核心、材料与 PROFILE 变更、过期回执、重复领取、中断重试、核心依赖断链、包内资源缺失、旧目录运行依赖、候选篡改；新增阶段依赖、版本/输入变化后的失效传播、预算停止及定向重跑。它们不增加用户审阅负担；ncc 编号/字段适配不在本轮回归范围。

真实业务至少包括一个书籍 Skill 与一个人物 Skill 的新任务实跑和迁移复跑、组合清单与原包一致、两书批量恢复且各有运行记录。对自然出现的失败完成阶段归因与定向修复；若未发生，只能报告恢复合同已测，不能声称已观察到返工收益。类型覆盖至少检验知识和思想/叙事两种不同用途；可复用同一运行材料，避免为形式增加重复任务。

拟晋级为通用的工作流修改还须在未参与调优的书上比较质量与成本；若缺材料，保留为局部改进候选。L1 验收是中间步骤，类型宣传按样本逐步开放，现行 L3 作者/整书任务仍按完整回答与用户口吻审阅判态。

交付记录分别列“代码已实现”“合同回归通过”“书籍/人物 Skill 在声明范围实际可用”“组合清单可用”“原包迁移后运行通过”“产能收益已观察”“该书 L3 已验收”。各项分别取证，不能用材料文件、导出统计或目标项目接口替代 Skill 的真实运行表现。历史会话中先报“P1 交付完成”、后承认真书未试产且命令未接通的情况，不作为完成证据沿用。
