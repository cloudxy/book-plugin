# 0.5 实施记录

两条主线均使用现有模型：按用途蒸馏书籍/人物 Skill；编排调度其生产步骤。正式作者分身及程序四闸仍使用原合同。操作入口见 [production.md](../../../skills/book-workflow/references/production.md)。

## 实现

| 能力 | 实现位置 |
|---|---|
| 全文分段、完整来源快照、书籍/人物输入、按用途提取、分组合并与综合 | `bridge/production.py`、`references/production-prompts.json` |
| 依赖执行、领取锁与租约、并发、预算、输入绑定、断点恢复及失效传播 | `bridge/production.py`、`production_common.py` |
| 单入口、能力条件、完整应用/变化范例、自包含试用包 | `bridge/distill_skill.py` |
| 实际调用当前配置的模型、每次独立临时会话 | `bridge/host_worker.py`；其他宿主可实现命令协议或 claim/collect |
| 实际答题、多轮逐次递交、独立评审、能力覆盖、答文与回执绑定 | `bridge/production_eval.py` |
| 原包及中立组合清单、版本/来源范围/依赖/已测条件、整体迁移、快照替换 | `bridge/skill_portfolio.py` |
| 有限反馈建议、阶段指令候选、同条件运行记录比较 | `bridge/workflow_optimizer.py` |

0.5 试用包使用 `distilled-skill/1`，不冒充 `book-skill/2` 正式作者分身；知识包不强制作者口吻。人物包需实际材料和真实产物，不能只登记姓名。逐字摘引在新线可选，所有声明原文仍进入阅读任务。

旧 `l1_extract.py`、`export_portfolio.py` 保留实验兼容，已标明不代表全文阅读或 Skill 可用性。`batch_runner.py` 识别新机器状态，并保留旧任务口径；没有要求旧任务补写新档位。

## 验证口径

`make e2e` 覆盖原程序12项、思想25项、作者15项、旧原型13项、新生产16项，合计81项；`make doctor` 检查环境与原闸门。新生产测试使用原创合成材料和显式模拟宿主，只证明合同与控制流程。技能入口同时通过 `skill-creator` 的结构校验。

独立前向测试发现并修复了依赖失效顺序、损坏包恢复、评审字段/分数篡改、能力覆盖删减、未列出答文、评审身份混用、组合清单元数据漂移及原包 manifest 变更问题。完整答文和评审写入后保持记录哈希；新评测另开目录。哈希用于内容绑定，不证明判断正确，也不是对有权改动所有本地记录者的防伪认证。

真实试产、答文、评审与运行记录位于私有 `books/`、`.work/`，不得提交。程序测试通过、实际 Skill 可用、可迁移交付及产能收益分别取证；不以版本号或文件数代替业务完成。

本次真实试产完成两份书籍 Skill 和一份限定两封完整家书的人物 Skill：5个阅读单元实际进入执行器，3份候选分别经过独立来源复核。预先固定18道问题，并在能力目录生成后补5道开发题；共23题、26次逐轮回答，覆盖六类任务及13项能力的正常/变化条件，均达到本轮独立评审完成线。9题标作保留题，其余为开发题。所有答题会话仅取得迁移包内容与本轮问题，未取得评分标准。

原包及中立清单已导出，并复制到另一个目录验证全部资源和内容绑定。真实已完成产线再次运行未派发任务、未增加用量。一次综合漏填范例来源类型被拦截，保留失败记录后仅修复该元数据并独立复核，未重复阅读整书；命令执行器据此增加结构化输出约束。评审同时保留了建议前条件核查不足、补出题目未给事实等局部问题，达到完成线不代表无误。以上证据支持这些用途范围内的试用交付，不证明正式作者分身、全部书籍类型或稳定的生产成本收益。

另对每份产物选一题运行无 Skill 对照，共3题。六份答文隐藏变体标签后由同一独立评审评分：两题的来源方法贴合度从2分升至3分，另一题持平；应用与实用性三题均持平。这是小样本诊断，不能据此宣称稳定优于通用模型，亦未建立降本或提速对照。原验收评分保持不变，对照不作为发布许可。

## 效果边界

- 命令执行器与当前宿主协助执行均有明确协议。没有执行器不称无人值守；构建完成后仍须继续实际评测与交付。
- 已声明全文进入输入、分段结果齐备和独立复核共同形成证据，不声称机器能证明模型理解了每个字。
- 默认预算有限，过大上下文或预算耗尽保存断点并报告；用户范围不因预算自动缩小。
- 提示候选工具是小规模反馈搜索，未声称完整实现 MIPRO/GEPA，也未训练模型。跨来源效果需实测后才能推广；不会自动采纳候选或静默改已发布包。
- 运行隔离按实际宿主能力记录。新会话只取得迁移包及当前任务，不等于已证明操作系统禁止访问原工作区。
- 时延、累计任务时间、实际 token、费用和人工干预分开衡量；并发不自动代表更省钱，不承诺固定提速倍数。

上游方法采用：nuwa `1.0.0`，核对提交 `7c7edfeb9d90a28b1f79e7847e1ba27a698cdc24`；采用材料分层、人物框架、适用边界和跨情境验证方向，按本仓私有交付与用途合同适配。cangjie及其他vendor版本保持不变，没有修改其源码。
