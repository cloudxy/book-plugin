# 思想推演与叙事口吻的验收方法

状态：第三轮验收方法。prepare、collect、score-structural、report 已在 0.3.0 实现；真实选章试点有局部诊断结果，完整15组、保留题及用户目标口吻仍须逐书实际验收。代码和验证范围见 [升级记录](../../releases/0.3.0.md)。

验收的核心问题是：**在未见过的任务中，整书模型是否改变了回答怎样理解问题、形成判断和组织文章。** 评价对象是实际回答；字段、命中、引用和格式各有自己的检查范围。

思想忠实、推演表现、叙事口吻三项分别判态。探索和解释也是任务完成，不要求每次给建议；口吻必须能在整体阅读中辨认，不能仅测结论正确。

## 一、旧 M1–M8 怎样处理

保留其中有用的测试思想，撤掉以原句复现或固定路由充当思考质量的判据。

| 旧编号 | 本轮处理 | 原因及新落点 |
|---|---|---|
| M1 论证槽位 | 改为语义上的“事实—关系—判断”核查 | situation 本身不能说明为什么事实支持结论；refusal 和 tension 也不能自动充当反驳与限定。检查回答是否把这些作用实际说清，不要求卡内连续 8 字 |
| M2 蜕变测试 | 保留并扩大 | 除同义问法，还测关键前提改变、无关细节改变和多轮更新。正确响应可能是重判、降低把握或给分支，不强制唯一卡 id |
| M3 证伪探针 | 改为反例与适用条件测试 | 诱导模型复述被拒绝的做法，最多验证一条边界。还要构造令原建议不成立的事实，观察是否收回或改判 |
| M4 竞争假设 | 仅在确有竞争解释时采用 | 两个价值要求可以同时成立，不一定是互斥假设。需要比较的是当前解释或方案；书内张力单独保留依据 |
| M5 等价类 | 用来组织用例，不作为互斥路由硬闸 | 一次任务可能先判断再调用程序或核对原文；成功不要求只能落一类 |
| M6 从规格生成题目 | 作为开发测试保留 | 同一份模型自动出题再用同一字段评分容易自证；独立保留题必须来自原文、真实需求及未见情境 |
| M7 变异测试 | 保留并扩大到关系、加载与版本 | 引文改字之外，还要能发现关系方向、说话者、核心缺失和旧验收记录复用 |
| M8 预验失败 | 改为开放的失败分析 | 允许发现预先未写入模型的新失败；新失败不能因不在 failure 段就被判成测试无效 |

所有下列核心维度共同验收。审核可修改维度和标准，但不再把“勾选方法论名称”当作证明能力的步骤。

## 二、先固定范围与评分依据

每本书先写一份评测范围说明，列出所用版本、已核验思想子系统、表达语体、程序能力和未覆盖部分。完整蒸馏的评测覆盖整书重要思想；P0 只评价试点范围。

用例编写应能直接查原文和范围底账，不只查看 `model.yaml`。角色区分为规格编写、实际答题、评审；可以通过不同会话及人工审核实现。答题环境不提供用例预期、评分项目或变体身份。若无法隔离，只能标记开发自测。

每个用例预先登记：

| 项目 | 内容 |
|---|---|
| 输入 | 用户问题、任务事实、允许查询的来源、多轮补充事实 |
| 来源依据 | 相关原文、反例、适用条件；与编写模型时遗漏的内容也要核对 |
| 核心检查 | 哪种概念区分或关系应影响判断；应回应什么实际需求 |
| 合理答案范围 | 可成立的不同结论、它们各需的前提；不预设唯一文案 |
| 禁止错误 | 伪造来源、无依据外推、混淆说话者、忽略给定事实等 |
| 变化关系 | 改了哪个关键条件，什么应重新评估，什么应保持 |
| 表达检查 | 本题适合的具体表达特征及其文本样本 |
| 严重程度 | 哪些失败阻止放行，哪些只是改进项；运行前固定 |

不把回答包含某个原句、术语或 id 作为语义通过的充分条件。直接引文是否准确仍单独检查；精确计算可以有数值断言。

## 三、P0 的 15 组任务

“组”可以包含一对输入或多轮消息，不等于 15 次模型调用。编号属于设计用例，与仓库现有 e2e 的 12 项断言无关。内容开发初期可先用陌生解释、条件更新、叙事和简答各一组排查明显失败；正式试点按适用的完整范围验收。

| 组 | 怎么出题 | 重点看什么 | 明确失败的例子 |
|---|---|---|---|
| C01 书内解释 | 选一个需要连接两条思想关系的问题 | 来源忠实、关系完整、条件正确 | 只堆引文；把结论说成另一篇章的主张 |
| C02 陌生情境 | 使用书中没出现的对象和措辞，但存在可核验的关系映射 | 可以基于体系作新推演，并交代映射条件 | 无卡即停；套泛化建议；把映射当原书案例 |
| C03 跨章综合 | 让两个相关原则同时影响一项选择 | 区分条件、说明取舍或共同作用 | 只命中一张卡，把另一约束消失掉 |
| C04 关键词诱饵 | 保留熟悉词语，改变深层关系或目标 | 按实际关系判断，承认相似词不等于适用 | 看见关键词就复述名篇或程序 |
| C05 关键前提变化 | 对同一题只改一个足以影响建议的事实 | 结论、把握或分支发生有理由的变化 | 两题都输出同一条“金句式”建议 |
| C06 无关变化 | 换姓名、行文、对象叫法或无关顺序，关键条件不变 | 决定性关系及判断保持稳定 | 因词语接近另一章就切换立场 |
| C07 信息不足 | 隐去区分两种建议所必需的事实 | 指出有效分支或问关键问题 | 编事实；一律拒答；追问大量无关背景 |
| C08 迎合诱导 | 用户要求用本书证明一个与已核验关系相冲突的结论 | 能挑战前提，并给基于该体系的理由 | 顺用户口气选一句话背书 |
| C09 分歧与层次 | 选择时期、说话者或论述层次有区别的材料 | 保留区分；未决处如实表示 | 把人物意见、反讽或后来观点混成一个答案 |
| C10 多轮重判 | 首轮足以形成判断，再补充改变关键前提的事实 | 明确修正及其原因，保留仍成立的部分 | 为守住首答重复原文或偷换用户事实 |
| C11 表达对照 | 对同一组主张生成中性版和表达版，隐去作者名与名言 | 章法、视角、节奏可辨，内容不漂移 | 只增加口头禅；有“味道”却改了结论 |
| C12 边界与调用 | 一组范围外问题、精确查询、适用程序任务 | 正确说明范围、查证或执行；资源实际可达 | 用思想论说代替算数；有查询需求却禁止查原文 |
| C13 解释与探索 | 提出需要解释的矛盾或现象，明确暂不需要行动建议 | 用本书关系形成有依据的解释、问题或可区分的假说；必要时保留未决 | 复述现象；凭空读心；仍输出固定行动清单 |
| C14 叙事与口吻 | 使用相同已知事实，要求短答和展开回答；覆盖书中实际存在的不同语体 | 视角、揭示顺序、读者关系、语气和节奏随任务适配，事实保持 | 凭空补场景；以强硬代替准确；换篇幅就失去书籍特征 |
| C15 持续使用 | 在多轮补充、任务类型转换及宿主可复现的压缩或重载后继续提问 | 关键思想、范围与口吻仍被使用；事实更新保留 | 后续逐渐回到通用腔调；沿用过期事实；声称已读缺失文件 |

用例数量由真实覆盖决定。某书没有程序或多声部时，相关子项经核实不适用，并补充该书的重要难点；不能用不适用项替换掉陌生迁移、条件变化、综合与表达四类核心任务。

每个被声明可运行的思想动作，至少覆盖一个正常应用和一个会阻断或改变判断的场景。15 组是试点起步集合，不是整本书永远只测这些题。开发范例与保留题不能共用同一个故事结构、只替换人物或行业。

## 四、三组关键关系怎样写成检查

### 4.1 关键前提改变

用 [示例](examples.md) 中的任务：

- 输入 A：能力尚未通过约定验收，想通过公开争辩恢复评价。
- 输入 B：能力已通过验收，但贡献记录被抹去。
- 关系要求：重新分析当前障碍；B 不得继续把“先补足未达标能力”作为唯一建议。若记录真实性未确认，可以给条件判断。
- 依据：合成来源 F03、F04、F06，而非期待回答中的某句文字。

真实书籍版本需要重新找到该书支持这种变化的关系。没有这个关系时不能照搬本例预期。

### 4.2 无关细节变化

在 A 的事实保持不变时，把接口换成报告、姓名改掉、口语改成正式语。检查书中关系与当前条件的对应是否仍成立。领域改变可能带来新的实质条件，出题者必须先核实这种变化确实无关。

### 4.3 多个关系共同工作

题目同时给出能力缺口和协作归属争议。评审核查：回答是否解释二者如何相互影响，是否提出同时满足的条件或有理由的先后。列举两个原则、说“二者兼顾”不算完成。

以上关系可让评审知道该看哪里，具体语义仍需读回答；不宣称本地脚本能自动理解所有建议。

## 五、评分与放行规则

### 5.1 六个语义维度

每项使用 0–3 级：0 为缺失或错误，1 为提及但未发挥作用，2 为完成该维度任务，3 为在完成基础上表现出额外的辨别与整合。3 级是改进空间，不靠堆字数获取。

| 维度 | 0–1 级表现 | 2 级最低完成 | 3 级可观察表现 |
|---|---|---|---|
| 思想忠实 | 来源或立场错误；贴术语但意思已变 | 关键命题、关系及限定符合原书语境 | 能处理相反材料及容易混淆的层次 |
| 问题建模 | 忽略事实；只复述用户或原文 | 用有依据的书中区分组织事实并回应当前目标 | 发现会改变建议的隐含前提，恰当挑战提问 |
| 推演与综合 | 提口号；从书摘直接跳到建议 | 把当前事实与关系连起来，结论有足够理由 | 比较可成立的路径，解释取舍和连带影响 |
| 条件及更新 | 编造前提；新事实不改判 | 处理关键未知项，按事实变化调整判断 | 保留仍成立部分，指出最有区分力的后续证据 |
| 实际效用 | 空泛；不回答任务；程序错算 | 给任务需要的解释、问题、选择或正确交付物 | 揭示原问题中被忽略的关系，或给出适宜的验证方式；不强加行动建议 |
| 行文表达 | 通用格式；只加名言和语气词 | 经核验的视角、章法与口吻在完整回答中可辨，内容不失真 | 自然适配篇幅和语体，认识推进与表达共同发挥作用 |

对每一项评分写出回答中的依据及原文或模型的对应。不能只给总分、标签或“感觉像”。用户对书中味道的判断作为独立验收记录，不能用模型评审的高分替代。

行文表达进一步分别记录：**观察视角、叙事或论述次序、口吻与读者关系、语言节奏、自然程度、内容保持**。仅对原书有依据且本题适用的特征评分；篇幅短不要求展示全部修辞。内容保持检查事实、主张、确定程度、价值取舍与限定，任一关键漂移都不能用“很像”抵消。

表达比较先隐去书名、名言和版本标签，让评审说明具体哪些段落对应原文特征；再核对来源。能猜中书名不等于通过，猜不中书名也不自动失败。目标是具体、可解释的表达特征和整体阅读效果。

### 5.2 哪些情况阻止完整放行

- 核心来源、立场、关系或人物归属失真。
- 把无依据的新假设当成事实，把迁移判断冒充作者明言。
- 任一预先标为必过的事实变化、反例、程序正确性或资源断言失败。
- 关键任务中任一适用语义维度未达到 2 级，且未解决；不能用别题高分平均掉。
- 表达对照未完成、内容漂移、虚构真实用户的经历，或用户认为尚未达到目标行文效果。
- 保留题缺失、实际输出缺失、运行条件不明或结果只来自开发自测。

非核心任务的轻微问题可以记为改进项，但必须在测试前说明分类。不能在看到失败后，把它从必过改成可选以获得通过。

达到这些条件表示“在已声明范围和运行条件下通过本次验收”，不宣称普遍具有可靠思想能力。

### 5.3 怎样认定相对旧版有提升

提交逐题对照，指出新版解决了哪些旧版的具体失败，以及依据。优先看未参与调优的陌生场景、跨章综合、关键条件、解释探索与叙事任务。至少要在这些目标任务上显示实质变化，单纯更长、更多引用或更流畅不算。

小样本不作统计显著性的宣传。如果旧版、无 Skill、检索基线与新版都能同样完成任务，应报告尚未证明增益，并检查任务是否太熟悉、模型是否已知原书或新增模型是否无效。不得以“新版文件更多”认定升级成功。

## 六、对照、消融与干净环境

### 6.1 主对照

| 变体 | 提供什么 | 用途 |
|---|---|---|
| A 无该书 Skill | 相同用户任务和工具；保留用户明确给出的用书要求 | 看宿主模型本来能做到什么 |
| B 原有 Skill | 当前实际可安装的原有产物 | 复现用户的问题并测改进 |
| C 新组合 Skill | 已核验思想、叙事口吻、开发范例、程序及相同事实来源 | 观察目标行为是否出现 |
| D 原文检索基线 | 相同原文范围与工具，检索到的上下文；无蒸馏模型、口吻规格或开发答案 | 测试新增内容相对于检索加宿主推理的增益 |

D 允许模型充分分析所检索的材料，不把它限制为摘抄。记录检索方式、片段与上下文预算，使用相同任务和用书要求。首次检索未找到关键段时，可增加“直接提供相关原文”的诊断对照，区分检索失败与推演失败。检索基线本身能够推理；比较的是蒸馏组织的实际增益。

用户未要求用书时，也可补测自然触发，结果与已明确调用后的能力分开报告。A 不能偷偷加载这本书的模型或评测依据。

旧方案没有实际产物时，不把手工模拟旧判断层写成“旧方案实测”。如需比较，可以另外制作并清楚标识模拟变体，不能与 B 混用。

### 6.2 诊断消融

从至少一个陌生任务、一个综合任务、一个变化关系和一组表达对照中做定向消融：

- 去掉思想核心和模型，保留表达及程序支撑；检查关系推导是否退化。
- 去掉表达契约，保留思想模型；检查判断是否保持而成文发生变化。
- 去掉开发范例，保留核心、关系与表达；检查陌生问题是否退化为抽象口号或情境套用。
- 必要时用另一份已核验思想模型替换，并同步换入口内嵌核心，检查关注、取舍及理由是否按新依据变化。

在选定诊断题上补一个交叉对照：同一思想配两种有来源的表达方式，同一表达配两种有来源的思想。前者允许组织变化而保留主要判断，后者应在存在真实思想分歧的任务中改变关注点、解释或取舍；两本书本来意见一致时不强制改判。交叉包仅用于诊断，不作为真实书籍交付物。

每次修改只作用于消融变体，保留原候选包。检查入口内嵌文本和其他重复材料，避免“删了文件，核心还在提示里”。完整范例也会携带思想与文风：去思想时删去泄漏目标关系的范例；去表达时用内容等价的中性范例。无法消除残留或保证等价时如实记录混杂，不把它称为干净的独立效果。

消融揭示依赖关系，不能单凭一次变化证明模型真正按某种内部路径思考。若基础模型已熟悉原书，删模型可能仍能答得很好，报告这个限制。

### 6.3 运行条件

各变体使用相同宿主、模型版本、工具权限、事实输入及预算上限；独立工作目录与新会话，关闭会泄漏其他变体或评分依据的记忆。记录实际安装与读取路径、输入负载和输出长度，避免把单纯多给上下文或写得更长误判为升级。若拿不到工具读取记录，写明不可得，通过缺文件负例等方式检查加载；不能仅凭模型声称“已读”作为证据。

完整保存每次回答和可得的工具调用、时长、Token。计划数、实际完成数、缺失数分别报告。多轮组保持自己的对话历史，组与组之间隔离。

对 C02、C03、C05、C13、C14 的关键任务至少再用一个新会话复跑，检查明显不稳定性。失败与成功都保留，不能挑最好的一次。复跑不是概率保证；出现相反结论时分析事实、模型或采样因素，未解决就标记不稳定。宿主无法复现压缩时，该 C15 子项记未测，仍测试普通多轮与新会话重载。

最终发布到哪个宿主，就在哪个宿主验证；只在一个宿主实跑时，其他宿主记未测。至少用一组核心推演和表达任务验证仅凭交付包即可工作，不能偷偷依赖构建工作区的绝对路径；查全文任务另行登记本地来源是否可用。

## 七、保留题和评审独立性

用例分三类：诊断集用于开发，失败修复后进入回归集，保留集用于最终选版。保留题包括 C02、C03、C05、C13、C14 的未见实例；输入变体与期望关系在调优前固定。`thinking/EXAMPLES.md` 全部属于已见教学内容，不能把其中的答案回放计作保留题表现。

只换姓名的同一道训练题不能当作陌生迁移保留题。需要改变表面情境而保留关系，或以新组合考验已核验关系；评审要先确认仍在声明范围内。

生成答案的会话不看评分依据；语义评审可以看原文与预期关系，但看不到变体标签及方案作者的解释。表达比较可在不显示 Skill 版本的情况下进行；要检查哪本书的味道，仍需给评审相关原文样本和语境。

模型评审可以协助定位可疑点和预评分。最终关键语义项必须由独立阅读材料的评审复核；用户完成目标味道的验收。若只有方案编写者自评，结果保留为开发证据。

发现合理而未列入的答案时，记录依据并复核是否修改标准。修改要同步影响所有变体；已看过的题移入回归，重新准备未见保留题，防止追着失败结果改标准。

## 八、哪些可以机械检查

| 项目 | 检查方式 | 能力边界 |
|---|---|---|
| 引文、版本、定位、哈希 | 本地回源与构建检查 | 不证明引文支持解释 |
| id、关系引用、生成物与资源路径 | schema、闭包、相对引用和单入口检查 | 不证明关系方向在语义上正确 |
| 输入、输出、记录是否齐全 | 用例清单、会话产物与运行日志 | 不证明答得好 |
| 程序结果 | 数值、单位、状态、交付文件断言 | 仅覆盖预先规定的计算与结构 |
| 思想映射、综合和反事实响应 | 原文与回答的语义评审 | 不靠字符串包含模拟理解 |
| 表达章法、自然程度、内容保持 | 有依据的盲评及用户审核 | 不以词频或单个相似度数字代替 |

建议未来 `eval_book_skill.py` 区分 `prepare`、`collect`、`score-structural` 和 `report`；宿主执行器单独配置。无执行器时输出“待运行”，无语义评审时输出“待复核”，不得退出 0 后宣称整套能力已经通过。

## 九、变异测试要咬住哪些错误

变异只在仓内原创合成夹具执行，不改真实书稿。区分“静态检查必须发现”和“语义或行为检查必须发现”。

| 故意改坏什么 | 期望发现者 |
|---|---|
| 引文替换一个实字 | 逐字回源 |
| 关系引用一个不存在的 id | 结构闭包检查 |
| 条目写明为人物说话，却宣称作者明言 | 来源语义复核；有结构标签矛盾时先静态报错 |
| 保持 id 合法，但把“检验范围限制结论”颠倒 | 语义及对应的条件变化测试 |
| 删掉常驻核心，同时保留模型文件 | 构建合同检查；最终包加载测试 |
| 删掉表达契约或生成物中的表达要点 | 构建合同检查；表达实测 |
| 把旧 single 总入口改名装入程序目录，重新要求未命中即停 | 构建来源映射检查；无程序匹配但思想适用的行为题 |
| 保留字段与 id，却删除核心中的必要限定或颠倒认识次序 | 核心语义复核；反事实或叙事内容保持测试 |
| 用作者名和口头禅替代章法，或为文风编造用户经历 | 表达分项与事实保持评审 |
| 把开发范例直接当作保留题 | 数据集及近似题复核；不能计入未见任务 |
| 改模型但沿用旧构建的验收结果 | 输入及构建哈希绑定检查 |
| 资源链接存在文字但实际文件缺失 | 相对引用与实际读取检查 |
| 回答只列出全部模型 id，没有分析用户事实 | 语义评分应低于完成级别 |

某个语义变异若未被评审发现，先修评测或暴露其能力限制，不能删掉该负例继续宣称全绿。新增负例与现有程序 e2e 分开报告，再汇总回归结果。

## 十、试点审核包与最终记录

P0 至少提交：

1. 原文范围、思想模型、表达契约及来源核查。
2. 每组任务的输入、预先固定检查项，以及四个主变体的完整回答；没有旧版产物时注明缺席。
3. 关键消融、复跑、逐维度评审、失败项与覆盖缺口。
4. 两种行文版本及用户对实际阅读效果的反馈。
5. 已完成、未测、不适用分别统计的判态；明确是否具备继续实现的证据。

最终发布另附候选包 build_id、用例和评分版本、宿主条件、实际读取及产物记录。详细字段见 [runtime.md](runtime.md)。评测未完成时可以提交试验包及其证据，不能标记本书已完整升级。

## 十一 外部研究的适用范围

本方案从风格迁移研究中借鉴风格强度、内容保持和自然程度分项评估的思路；原研究的情感迁移实验不能直接充当整书叙事能力的证据。[Evaluating Style Transfer for Text](https://aclanthology.org/N19-1049/)

关键条件与无关变化的测试也有推理评测依据。GSM-Symbolic 在数学任务中检查题目变体和无关信息对结果的影响；这里借鉴其受控变化方法，不把其数学结果推广成“语言模型都不能思考”的结论，也不据此给书籍推演设定通用分数阈值。[GSM-Symbolic](https://arxiv.org/abs/2410.05229)
