# 0.5.2：补齐产线升级方案中未完成的要求

依据：[生态融入与产能升级方案（修订稿七）](../designs/ecosystem/upgrade.md)。0.5.0/0.5.1 交付了执行链，但方案的核心要求没有落实：升级对象是整个工作流的生产能力，需要补齐阶段运行记录、失败归因、定向返修、跨书改进和工作流版本对照。真实运行中跨书反复出现的问题，当时靠私有脚本和手改策略按单本书处理。本版把这些问题收回工作流。

## 补齐项

| 方案要求 | 0.5.2 实现 |
|---|---|
| §四.5 失败归因决定返修位置 | 复核返回 repairs，可退回读、合并或综合；抽查失败的单元定向重读，并扩大到相邻单元；评测失败由独立评审按阶段归因（read/synthesize/examples/build/evaluation/unknown），退回阅读或综合，或记为工作流/评审器问题；返修轮次有界，后续评测确认或否定归因 |
| §四.6 两层优化循环 | `production.py cycle` 是单书循环。`workflow_optimizer.py failures` 汇总多书中已归因的失败，只有跨书重复的问题才成为工作流候选；`propose` 每次只改一个阶段模块的一处；经验账本只在未参与调优的书上做 held-out 对照、质量不退步后才把规则升为全局 |
| §二 工作流 Skill 有明确合同、范例、失败处理 | 新增 `production-modules.json`：每个阶段声明输入、输出、来源范围、依赖、执行者、工具、预算及失败退回目标，配合成范例与失败处理规则；运行时固定所用模块集 |
| §四.2 类型模板产生不同内容 | 论说、叙事、连载、诗词、科学五种体裁模板，各自规定阅读阶段提取的对象类型、声音分层和必守边界；人物另加自述、他人评价、后世解释三种声音 |
| §三 L2 按用途配资产与评分 | 思想用途必须有 episodes 与 habits，表达用途必须有 PROFILE；每项能力标声音和材料边界（书内主张现实未核、故事内机制、方法观点）；评分维度按用途加作者认知或表达，不适用的写明理由 |
| §三 L1 抽样、返修与有限交付 | 按来源与位置分层、带种子、样本量 min(N, max(10, ⌈0.1N⌉)) 的独立抽查，另加风险条目；失败单元定向返修，超过轮次即隔离并列出缺口；产出 L1 阅读底账、类型条目、overview 与抽样回执 |
| §四.3 状态与档位 | 记录 target_tier（L1/L2，拒绝 L3）；生命周期为 queued→reading→reconstructed→reviewed→built→tested→delivered，异常为 failed/blocked/stale |
| §四.1 输入登记与定位 | 登记版本/译者、正文边界与排除范围、来源问题；每个单元可回到行号、章节、页码或时间码；人物多来源各带角色、时期、URL 和可访问范围 |
| §四.3/§四.7 有限退避重试、预算 | 错误分为暂时性、超时、结构性、合同四类；暂时性错误指数退避，不消耗语义尝试次数；各阶段有各自的超时；墙钟截止时间可跨机器休眠；租约过期但未被重新领取的结果照常收下；运行器不因迟到结果退出；开跑前给出预算预估 |
| §四.4 只装载依赖闭包 | 复核或抽查包超出预算时，自动分批交独立会话、由脚本汇总；宿主拒收超大输入后，自动降低已知上限并重新分批 |
| §二 收益按质量与资源分项衡量 | `metrics` 分项报告首个可用 Skill 耗时、墙钟时间、累计任务时间、token、评测成本、人工干预、自动返修、各阶段一次通过率、重复调用原因与缓存复用；`compare` 只在同来源、同范围、同档位之间对照 |
| §七 交付记录分项取证 | `record` 写出七项，每项单独取证 |
| §五.3 可发现、可加载 | `--loading host` 把包放进新项目的 `.agents/skills/`，不内联，由宿主自行发现；以工具事件观察到的读取路径为准，入口没被加载判失败 |
| §五.1 组合清单字段 | skill-portfolio/2 增加触发条件、输入、能力、包版本、内容哈希、已测用例、宿主和加载方式；待构建条目单列，不计入可用 Skill |
| §七 第309行 engine_hash 隔离 | 只对 0.4.0 解释器和构建依赖取哈希，新线模块的改动不再影响正式候选的构建来源 |
| §四.3 缓存与恢复 | 缓存键不含源码哈希；0.5.0 的旧键先逐项核对再换新；人工改策略、解除阻塞和重试都要通过命令，记为干预 |

## 兼容

- 0.5.0 开跑的任务继续使用当初固定的扁平指令与旧结果合同。旧缓存键核对通过才沿用：用三本私有运行状态的副本实测，已完成的 23、39、271 项全部沿用。
- `distilled-skill/1` 包、`skill-portfolio/1` 导出和第 1 版评测记录照旧校验。三份旧评测报告在新代码下重新核对，结论与证据哈希不变。
- 正式作者分身（`book-skill/2`）、程序四闸与毛选 L3 任务的合同不变。engine_hash 的计算范围变了，影响见实施记录。

## 验证

- `make e2e`：141 项通过。新增的生产合同、单书循环、抽查返修、人物来源、档位、退避运行器、优化器与宿主加载用例，全部使用合成材料和假执行器。
- 用私有运行状态的副本做了只读兼容核对，没有修改 `books/` 与 `.work/`。
