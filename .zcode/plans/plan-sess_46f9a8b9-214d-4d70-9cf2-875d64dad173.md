# book-workflow tests 全方位调整 + 测试体系架构设计

## Context

tests/ 现状（已核实）：6 个文件 1262 行 = 73 个 unittest + 12 项 e2e 脚本检查，全绿约 14s。问题：
1. **双范式**：e2e_test.py 是手写 check() 脚本，其余 5 个是 unittest；production_test.py / persona_test.py 是分号压缩风格，难维护。
2. **隔离缺陷**：e2e 直接写仓库共享 `.work/demo-book`；负向 5/6 **就地改写 tests/fixtures 下的 svg/card 再手工恢复**（中途崩溃会留下损坏 fixture）。
3. **脚手架重复**：approve_fixture / suite 构建 / populate_run / synthetic_source 在 4 个文件里近乎复制（~150 行）。
4. **覆盖缺口**：host_worker.py 零测试；batch_runner 产线分支、workflow_optimizer.propose、worker_schema read/merge 段、render_html_image 守卫均未测；缺口无机制可见。
5. Makefile 逐文件列举运行器；文档硬编码"12 项断言"会腐烂。

已定决策：**stdlib unittest（零新依赖）、不加 CI（文档预留演进位）、设计范围=测试体系架构**。不改 bridge 产品代码、不动 vendor/、不改 dsh 源码。

## 实施阶段

### Phase 0 — 基线固化
抓取改造前测试清单证据：`.venv/bin/python -B -m unittest discover -s tests -p '*_test.py' -v` 输出存档，作为重构等价性对照（同名同数同结果）。

### Phase 1 — 结构重组（行为等价）
1. **`tests/support/` 共享脚手架**（新包，`__init__.py` + `books.py` + `contracts.py`）：
   - books.py：`synthetic_source()`、`bucket_entry()`（自 pipeline_test.py:19-31 提出）
   - contracts.py：`approve_fixture()`、suite 构建、`populate_run()`（自 thinking_test.py:37-87 与 persona_test.py:33-80 去重）
2. **统一命名 + discover 运行器**：
   - e2e_test.py → **test_gates_e2e.py**（脚本改写为 unittest 类，12 项检查语义逐条保留，print 输出保留）
   - thinking_test.py → test_thinking_contracts.py；persona_test.py → test_persona_contracts.py；pipeline_test.py → test_pipeline_contracts.py；production_test.py → test_production_contracts.py；vendor_test.py → test_vendor_regressions.py
   - Makefile：`make e2e` → `$(PY) -B -m unittest discover -s tests -p 'test_*.py'`；thinking-test/pipeline-test/production-test/vendor-test 用 `-k` 过滤保留；删除已无对象的 `clean` target
3. **e2e 全面临时目录隔离**（复用 thinking_test.py:352-358 已验证模式 + run_audit.py:72 的 `DSH_DISTILL_ROOT`/`DSH_WORKSPACE_ROOT` env 模式）：
   - setUpClass 建 temp ws：拷 tools/ → ws/tools、mkdir .dsh、拷 fixture 书与源文为副本
   - 桥接/判态带 `--ws`；闸门直调带 env+cwd
   - 负向 5/6 在副本上篡改，**tests/fixtures 与仓库 `.work/` 永不被写**

### Phase 2 — 风格归一（oracle 逐一等价）
test_production_contracts.py / test_persona_contracts.py 机械展开为标准 Python（分号→换行、恢复间距），断言与测试名逐一不变，Phase 0 清单 diff 证明等价。

### Phase 3 — 补覆盖缺口（新增测试）
全部针对**现有守卫行为的特征测试**，无需制造红（tdd 技能：characterization 不强求红）：
- **test_host_worker.py**：假 codex 可执行注入 PATH，验证 JSON 信封（thread.started/turn.completed 事件解析、--output-schema 附着、rc≠0 失败路径、非 JSON 行忽略）
- **test_batch_runner.py**：pipeline/state.json 产线分支（book_state 走 production status）、next_action 的 stale-source/built-pending 分支、tier/slug 过滤、portfolio 排除
- **test_workflow_optimizer.py**：propose() 分支（stage:none / 合法 stage / 未知 stage ContractError / out 已存在 ContractError），经假 worker 命令
- **test_worker_schema.py**：read/merge 段 schema（现有仅 synthesize/review）
- **test_render_html_image.py**：仅守卫（banned()/read_text 三条拒绝分支、无密钥拒绝 rc=2 不发网络）
- **tests/COVERAGE.md**：bridge 20 个模块 ↔ 属主测试映射（或显式"不测理由"）
- **test_coverage_map.py**：合同测试，断言 bridge/*.py 每个模块都在 COVERAGE.md 登记 —— 缺口从"靠 grep 发现"变为"make e2e 强制可见"

### Phase 4 — 架构设计文档 + 文档同步
**docs/designs/test-architecture.md**：
- 质量场景：防假绿、隔离、<30s、缺口可见、多机 git pull 后零手工
- 分层：单元合同（进程内）/ 集成闸门（子进程链+临时 ws）/ vendor 固定版回归 / 映射合同
- 不变量：合成素材 only、无网络、临时目录隔离、期望值独立于被测实现（字面量）、fixtures 只读
- ADR-lite：unittest vs pytest（选 stdlib，自包含纪律优先；revisit trigger：参数化需求爆发再议）；discover 运行器；DSH_DISTILL_ROOT 隔离（不改 dsh 源码）；coverage map 而非 coverage 工具（零依赖）；CI 不加（附 Actions 清单草案作演进预留）
- 演进规则：新 bridge 模块 ⇒ 必须同步属主测试 + COVERAGE.md 登记（test_coverage_map 强制）；vendor 升级 ⇒ vendor_test 同步行为回归

文档同步：AGENTS.md（tests/ 目录描述、"12 项断言"改为不腐烂口径）、README.md 测试章节。
